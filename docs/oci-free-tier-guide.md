# OCI Object Storage を完全無料で使うためのガイド

この Worker と組み合わせて、**1 円も課金されない状態を保ったまま** OCI Object Storage を静的ファイル配信に使うためのメモです。

> 無料枠の内容は変わることがあります。数字は 2026 年 11 月時点で Oracle の公式ドキュメントを確認したものです。
> 最新情報は [Always Free Resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm) と [Free Tier FAQ](https://www.oracle.com/cloud/free/faq/) を確認してください。

## 1. 無料枠でできること

| 項目 | Always Free の上限 | 備考 |
|---|---|---|
| ストレージ容量 | **合計 20 GB** | Standard / Infrequent Access / Archive の合算（Always Free のみのアカウントの場合）※ |
| API リクエスト | **月 50,000 回** | GET・PUT・LIST などすべての操作が対象 |
| 外向き転送量 | 月 10 TB | 現実的にはまず使い切らない |
| リージョン | **ホーム・リージョンのみ** | アカウント作成時に選び、後から変えられない |

※ Pay As You Go（従量課金）にアップグレードしたアカウントや、トライアル・クレジットが残っている間は、Standard / Infrequent Access / Archive が各 10 GB という配分になります。

いちばん厳しいのは **月 5 万回の API リクエスト**です。1 日あたりにすると約 1,600 回なので、Web サイトの画像をそのまま配信するとすぐに使い切ってしまいます。
この Worker は Cloudflare でキャッシュして、OCI へのリクエストをキャッシュミスのときだけに減らすためのものです。

## 2. 「完全無料」を保つためのアカウント運用

### アカウントは Pay As You Go にアップグレードしない

- 申し込みにはクレジットカードが必要ですが、本人確認のためで、**アップグレードしない限り課金されません**。
- 最初の 30 日間は無料トライアル（クレジット）期間です。期間が終わると「Always Free のみ」のアカウントになります。
- **Pay As You Go にアップグレードすると、無料枠を超えた分が課金されるようになります。** 完全無料を貫くならアップグレードしないでください。
- Always Free のみのアカウントでは、無料枠を超えた使い方はできない（課金されるのではなく、制限されたり作れなかったりする）、というのが基本的な考え方です。

### トライアル終了時の容量に注意

トライアル期間中は 20 GB を超えて保存できてしまいます。**トライアル終了時に 20 GB を超えていると、オブジェクトがすべて削除されます**（公式 FAQ に明記）。
トライアル中も 20 GB 以内に収めておくのが安全です。

### ホーム・リージョンにバケットを作る

Always Free はホーム・リージョンでしか使えません。バケットは必ずホーム・リージョンに作ってください。
ホーム・リージョンは、コンソール右上のリージョン選択に「ホーム」と表示されています。

### 予算アラートを設定しておく（保険）

コンソール → 請求とコスト管理 → **予算** で、たとえば月 100 円（1 ドル）程度の少額の予算と、実績が 0 を超えたら通知するアラートを作っておくと、何かの理由で課金が発生しそうになったときにメールで気づけます。

## 3. バケットの作り方（推奨設定）

1. コンソール → ストレージ → オブジェクト・ストレージ → バケット → **バケットの作成**
2. 次のように設定します。

| 設定 | 推奨値 | 理由 |
|---|---|---|
| デフォルト・ストレージ層 | **標準** | Archive は取り出す前にリストアが必要で、配信には使えない |
| 自動階層化 | 無効 | 意図しない層移動を避けるため |
| オブジェクトのバージョニング | **無効** | 有効にすると上書き前の古い版が残り、20 GB を消費し続ける |
| 可視性 | **プライベート** | パブリックだと OCI を直接叩かれ、リクエスト枠を消費される |
| オブジェクト・イベントの発行 | 無効 | 不要 |

3. 配信用には、この Worker の README にあるとおり **バケット単位・読取り専用の事前認証済リクエスト（PAR）** を作成します。

### ライフサイクル・ルールで不要データを掃除する

バケット → ライフサイクル・ポリシー・ルール で、**未コミットのマルチパート・アップロードを数日で削除する**ルールを作っておくと安心です。
大きなファイルのアップロードが途中で失敗すると、目に見えない断片が残って容量を食うことがあります。

## 4. API リクエスト数を節約するコツ

**OCI にリクエストが飛ぶ操作**は配信だけではありません。

| 操作 | リクエスト数の目安 |
|---|---|
| Worker 経由の配信（キャッシュミス時） | 1 オブジェクトにつき 1 回 |
| アップロード | 1 ファイルにつき 1 回。マルチパートなら「パート数 + 2〜3 回」 |
| コンソールでオブジェクト一覧を開く | 表示のたびに数回 |
| `oci os object bulk-upload` / `rclone sync` など | 一覧取得（1,000 件ごとに 1 回）＋ファイルごとの確認・転送 |

- **配信側**: Cloudflare のキャッシュ期間（`EDGE_CACHE_TTL`）を長くするほど OCI へのアクセスが減ります。ファイルを更新するときは、パージするよりファイル名を変える（`style.v2.css` など）方がリクエストの節約になります。
- **アップロード側**: 変更されたファイルだけを送るようにします。rclone なら `rclone copy --size-only` や `--update`、OCI CLI なら `oci os object sync` など、差分だけを送る方法を使ってください。
- **コンソール**: オブジェクト一覧のページを開いたままにしたり、何度も再読込みしたりしないでください。

### どのくらい配信できるか（目安）

Cloudflare のキャッシュはデータセンターごとなので、OCI へのアクセス数はだいたい次のように見積もれます。

```
月間の OCI GET 回数 ≒ よく見られるオブジェクト数 × アクセス元の Cloudflare データセンター数 × キャッシュが入れ替わる回数
```

例えば、日本国内向けのサイトでオブジェクト 1,000 個・データセンター 3〜5 か所の場合、キャッシュが一度ずつ入れ替わったとしても月 3,000〜5,000 回程度で、5 万回には十分余裕があります。
ただし Cloudflare は、アクセスの少ないファイルを TTL より前にキャッシュから追い出すことがあります。アクセスがまばらで種類の多いファイル（何万枚もの画像など）では、ミスが増えることを見込んでおいてください。

## 5. 使用量の確認方法

- **容量**: バケット詳細の「おおよそのサイズ」と「おおよそのオブジェクト数」
- **リクエスト数**: コンソール → 監視および管理 → メトリック・エクスプローラ で、ネームスペース `oci_objectstorage` のメトリック（`AllRequests` など）を見る
- **課金状況**: 請求とコスト管理 → コスト分析。0 円になっていることを確認
- **上限**: ガバナンスと管理 → 制限、割当ておよび使用状況

Cloudflare 側では、Worker のダッシュボードでリクエスト数を確認できます。レスポンスヘッダ `x-cache` が `HIT` になっていれば、OCI へのアクセスは発生していません。

## 6. Cloudflare 側の無料枠

| 項目 | 無料プランの上限 |
|---|---|
| Workers リクエスト | 1 日 10 万回（キャッシュ HIT も 1 回と数える） |
| Workers CPU 時間 | 1 リクエストあたり 10 ms（この Worker はほとんど使わない） |
| CDN 転送量 | 実質無制限（ただし大量の動画配信などは規約に注意） |

Workers の 1 日 10 万回を超えるとエラーが返るようになりますが、課金はされません（Workers Paid プランに入っていない場合）。
